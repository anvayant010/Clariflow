# Evaluation: naive baseline vs Clariflow (2026-11-05)

**Mode:** recorded transcripts, no live API calls. Transcripts are RECORDED Prisma v3.0 output from 2026-11-04 (cache in evaluation/results/gate_cache.json); this report made no API calls. 'Naive' audio rows use plain verbatim STT; Clariflow rows use format=codemix + keyterms (decision D12; the keyterms are our own asset IDs).

**What 'naive' means:** A baseline we wrote, not a real product: the same transcript parsing as Clariflow, then 'save as heard' with no checks (first asset candidate, Celsius assumed, spoken hour kept as-is, missing unit left blank, contradictions saved as fact, last value wins, nothing asked). On audio it uses plain verbatim STT.

## Caveats

- Truth records were written by Claude, the same author as the extractor, from the scripts the speaker was asked to read; no second person has checked them against the audio.
- Audio set: 9 clips, one speaker (Anvay), quiet room, Marathi/Hindi/English mixes. Not real factory or telephone audio.
- The 57 written transcripts were used while fixing the extractor, so they measure regression, not unseen-data accuracy. The only first-run unseen figure is 15 of 18 (see docs/PROGRESS.md).
- The naive baseline is one we wrote (see its definition above); a real summariser or LLM pipeline could do better or worse.
- Clariflow's numbers are its draft BEFORE a human answers. It cannot save until questions are resolved and the user confirms.
- Counts are checked items against truth, not a probability of correctness, and no confidence interval is claimed.
